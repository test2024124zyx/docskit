# DocsKit Markdown 参考

本文件描述 DocsKit 支持的 Markdown 写法。编写文档时以这里的语法为边界，不要根据 CommonMark、GFM 或其他站点的额外能力推断 DocsKit 会支持。

## 文件发现与默认元数据

- 文档文件使用 `.md` 或 `.markdown` 扩展名，扩展名不区分大小写。
- 隐藏文件、隐藏目录和 `node_modules` 不会出现在文档导航中；`docs.config.json`、图片和其他资源也不是文档页面。
- 目录会生成导航分组，文件会生成导航项；目录层级会保留在侧边栏。
- 文档标题按以下顺序决定：front matter 的 `title`、正文第一个 Markdown 标题、由文件名推导出的标题。
- 文件名推导会去掉扩展名、开头的数字前缀以及连字符和下划线，并将首字符转为大写；`README.md` 或 `index.md` 位于子目录时默认使用父目录名称，根目录文件则使用“首页”。
- 未设置 `description` 时，DocsKit 会从正文前面的第一个段落提取摘要，去除部分 Markdown 标记后最多保留 130 个字符。
- front matter 不会显示在页面正文中。

文件名建议使用稳定的短路径，例如 `guides/configuration.md`、`api/authentication.md`。文件名数字前缀会影响显示标题，但不会单独决定排序；需要明确顺序时使用 `order`。

## Front matter

Front matter 必须从文件第一行开始，用单独一行的 `---` 开始和结束。DocsKit 使用轻量解析器，只识别每行一个简单键值，不是完整 YAML 解析器。

```markdown
---
title: 文档结构
description: 介绍 DocsKit 文档的基本结构和写作方法。
order: 1
icon: download
hidden: false
---

# 文档结构
```

### 支持字段

| 字段 | 类型 | 行为 |
| --- | --- | --- |
| `title` | 字符串 | 覆盖标题推导结果，并显示在导航、搜索和页面中。 |
| `description` | 字符串 | 覆盖自动摘要，显示在页面元信息和搜索结果中。 |
| `order` | 数字 | 同级排序的第一比较项，数值越小越靠前；可使用负数和小数。 |
| `icon` | 字符串 | 设置当前 Markdown 文件的默认图标；全局路径图标和类型默认图标优先级更高。 |
| `hidden` | 布尔值 | 只有写成未加引号的 `true` 才会隐藏文档；隐藏文档不进入导航、搜索和公开文档索引。 |

解析值的规则如下：

- 双引号或单引号包住的值会去除外层引号。
- 未加引号的 `true` 和 `false` 会解析为布尔值。
- 整数和小数会解析为数字。
- 其他内容按字符串处理。
- 不要写嵌套对象、数组、多行字符串、锚点、变量或 YAML 标签。数组形式的 `keywords` 只适用于 JSON 配置，不适用于 front matter。
- 如果结束 `---` 缺失，DocsKit 不会把它当作 front matter；应修复分隔线而不是依赖容错行为。

### 标题和摘要示例

```markdown
---
title: 站点配置
description: 说明文档标题、摘要和导航顺序的配置方式。
order: 2
icon: shield-check
---

# 站点配置

本文介绍如何为站点配置文档标题、摘要和导航顺序。
```

没有 `title` 时，正文中的第一个 `#` 到 `######` 标题会作为标题。没有 `description` 时，使用标题之后或正文开头的第一个非空段落。为了让导航和搜索稳定，建议显式提供 `title`、`description` 和 `order`。

## 块级语法

### 标题

支持一到六级标题，每行允许最多三个前导空格，格式为 `#` 加空格再加标题文字。标题会自动生成 `id`；页面右侧目录只显示二至四级标题。

```markdown
# 一级标题
## 二级标题
### 三级标题
```

建议每篇文档只有一个一级标题，用二级标题组织主要章节，用三级标题组织章节内的步骤或概念。不要跳过多个层级来表达视觉样式。

### 段落

连续的非空行会合并为一个段落，空行分隔段落。段落中的单个换行不会自动生成 `<br>`；需要明确的分段时插入空行。

```markdown
这是第一段的第一行。
这是第一段的第二行。

这是第二段。
```

### 围栏代码块

支持三个或更多反引号、三个或更多波浪号，围栏前最多允许三个空格。第一行围栏后的第一个无空格标记会显示为语言名称，未填写时显示 `code`。

````markdown
```json
{
  "enabled": true
}
```
````

```markdown
~~~text
这是使用波浪号围栏的代码示例。
~~~
```

代码块按原文显示，不会把代码内容当成 Markdown 语法解析。围栏必须闭合；未闭合的围栏会把文件剩余内容都当作代码。

### 分隔线

由同一种 `-`、`*` 或 `_` 重复组成的分隔线会渲染为水平线，字符之间可以有空格。

```markdown
---
***
_ _ _
```

文件第一行的 `---` 有 front matter 特殊含义；正文中的 `---` 才按分隔线处理。

### 表格

表头行必须包含 `|`，下一行必须是每列至少三个连字符的分隔行。分隔行可以用冒号控制对齐：左侧冒号表示左对齐，右侧冒号表示右对齐，两侧都有表示居中。

```markdown
| 参数 | 类型 | 说明 |
| :--- | :---: | ---: |
| `title` | string | 文档标题 |
| `order` | number | 导航顺序 |
```

数据行需要连续且包含 `|`；空行会结束表格。不支持单元格内的转义竖线、复杂嵌套 Markdown 表格或跨行单元格。保持列数一致。

### 引用和提示框

连续的 `>` 行会渲染为引用块。

```markdown
> 这是普通引用。
> 可以包含多行文字。
```

第一行是以下标记之一时，会渲染为提示框：`NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION`，标记不区分大小写。

```markdown
> [!WARNING]
> 生产环境不要把访问令牌提交到代码仓库。
```

提示框标记必须单独占据第一条引用行，后续内容继续使用 `>`。空行会结束引用块。

### 列表和任务列表

支持无序列表和有序列表。无序列表使用 `-`、`+` 或 `*`，有序列表使用数字加点；列表项前最多允许三个空格。

```markdown
- 确定文档目标
- 组织章节结构
- 补充示例

1. 读取写作规则
2. 编写正文
3. 校对链接
```

列表中以 `[ ]`、`[x]` 或 `[X]` 开头的项目会渲染为禁用状态的复选框。

```markdown
- [x] 完成文档结构
- [ ] 补充示例
```

列表使用连续的同类列表项；不支持可靠的嵌套列表、列表项多段内容或列表中的复杂块级结构。需要表达层级时使用标题、表格或单独段落。

## 行内语法

支持以下行内写法：

| 写法 | 示例 |
| --- | --- |
| 行内代码 | `` `docs.config.json` `` |
| 粗体 | `**重点**` 或 `__重点__` |
| 删除线 | `~~已废弃~~` |
| 斜体 | `*强调*` |
| 链接 | `[安装](../getting-started/installation.md)` |
| 图片 | `![界面截图](../assets/screenshot.png)` |
| 内置图标 | `:icon[rocket]` |

行内内容会进行 HTML 转义。除表中写法外，原生 HTML 标签不会作为 HTML 执行；`_斜体_`、下划线、脚注、自动链接和复杂嵌套格式不要使用。

`:icon[名称]` 是 DocsKit 的内置图标扩展，只在普通 Markdown 文本中替换为 SVG 图标。名称必须来自配置参考中的 102 个内置图标；放在 fenced code block 或行内代码中的标记会保持原样。图标带有名称提示和无障碍标签，适合放在操作说明或图标清单中，不要用它替代导航图标配置。

链接和图片可以带单引号或双引号包围的标题：

```markdown
[配置文件](../api/configuration.md "查看配置说明")
![标志](../assets/logo.png "站点标志")
```

行内解析对目标地址的空格和右括号支持有限。目标地址保持不含空格，并对复杂 URL 使用外部完整地址或拆分为更简单的链接。

## 链接和资源

### 站内文档链接

从当前文档所在目录计算相对路径，建议始终写出 `.md` 或 `.markdown` 扩展名：

```markdown
[安装](../getting-started/installation.md)
[同目录 API](./api.md)
```

站内 Markdown 链接会打开对应文档页面。以 `#` 开头的链接会保留为当前页锚点；标题锚点规则见下一节。链接路径不要越出文档目录。

### 图片和本地资源

图片地址相对于当前文档目录解析：

```markdown
![架构图](../assets/architecture.svg)
```

远程图片可以使用 `https://`、`http://`、`data:` 等完整地址。本地图片应放在文档目录内。需要链接到 PDF 或其他下载文件时，优先确认项目对该资源类型的既有写法。

### 外部链接

`http://`、`https://`、`mailto:`、`tel:` 和 `data:` 目标会按外部链接处理，其中网页外链会在新标签页打开。不要把不可信的 HTML 或脚本协议写进文档。

## 标题锚点和页面目录

每个标题都会生成稳定的 `id`：文本会转为小写，去除大多数标点，把空白和连字符合并为连字符；中文字符会保留。相同标题会追加 `-2`、`-3` 等后缀。

```markdown
## API 请求
```

上例可以使用以下同页链接：

```markdown
[查看 API 请求](#api-请求)
```

标题中的图标、复杂内联格式和标点会影响最终锚点生成，写跨段落链接时应从实际页面检查 URL 片段。页面右侧目录只会列出二至四级标题，不需要手工维护目录列表。

## 隐藏文档

需要作为内部草稿、迁移记录或不希望出现在用户搜索中的文档时，将文档标记为隐藏：

```markdown
---
title: 发布检查草稿
hidden: true
---
```

隐藏文档不会出现在导航和站内搜索中；不要用它隐藏需要公开访问的页面。

## 不支持的语法

当前 DocsKit 文档不要生成以下语法：

- 原生 HTML、脚本、样式标签和自定义组件。
- 嵌套列表、定义列表、脚注、上标、下标和数学公式。
- Mermaid、流程图、时序图、PlantUML 或其他图表代码块的特殊渲染。
- YAML 数组、嵌套对象、块字符串和 front matter 插件字段。
- 表格中的转义竖线、跨行单元格和复杂块级内容。
- 自动识别裸 URL、`_斜体_`、链接引用定义和 Markdown 扩展属性。

需要表达这些内容时，使用普通文本、围栏代码、图片资源或拆分为多个 DocsKit 已支持的块，并向用户说明表达方式的限制。

## 完整示例

```markdown
---
title: 搜索文档
description: 使用关键词在标题、路径和正文中查找可见文档。
order: 2
icon: search
---

# 搜索文档

站内搜索适合查找配置、接口和操作步骤。

> [!TIP]
> 使用能准确描述目标内容的关键词。

## 操作步骤

1. 点击顶部的搜索入口。
2. 输入关键词。
3. 选择搜索结果打开文档。

## 示例关键词

| 关键词 | 用途 |
| --- | --- |
| `docs.config.json` | 查找站点配置 |
| `front matter` | 查找单篇文档元数据 |

## 相关文档

[查看配置文件](../api/configuration.md)
```
